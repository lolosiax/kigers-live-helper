## 1. 项目定位

- **Kiger's Live Helper（Kiger直播助手）**：Windows 桌面屏幕镜像工具。把一台显示器（或一个窗口）实时镜像到另一台显示器。
- 形态：C++/D3D11 原生核心（`native/`）+ Compose wasmJs 面板跑在 WebView2 里（`ui/`）
  + keel 薄插件负责物化与拉起（`keel-plugin-klive/`）+ 纯 Kotlin 共享模型（`core/`，KMP）。
- 包根 `moe.lolosia.klive`，Gradle 工程名 `klive`（仅缩写），版本 `0.1.0`；
  插件名 `Kiger's Live Helper`，日志模块列 `Kiger's Live`（`plugin.json` 的 `logTag`）。
- 长期方向：镜像/串流核心要能被其它 keel 插件（局域网 WebRTC / RTSP）复用，所以原生层只暴露 C ABI。

## 4. 已实现细节

### 4.1 原生层结构

| 文件 | 职责 |
| --- | --- |
| `include/klive.h` | C ABI：结构体布局 + 导出函数，**唯一布局来源** |
| `src/internal.h` | `KliveOutput`（枚举结果）、`KliveMirrorSession`（原子状态 + worker）、`SrwExclusiveLock` |
| `src/klive_exports.cpp` | 导出函数实现 |
| `src/klive_monitor.cpp` | DXGI 枚举显示器、`EnumWindows` 枚举窗口、错误消息缓冲 |
| `src/klive_mirror.cpp` | 镜像窗口（无边框置顶）+ 渲染循环 + 缩放 + 帧率统计 |
| `src/frame_source.h/.cpp` | `FrameSource` 接口、`FrameCopy` 中转纹理、DXGI 错误文案 |
| `src/klive_duplication.cpp` | 桌面复制后端（`ACCESS_LOST` 自动重建） |
| `src/klive_wgc.cpp` | WGC 后端（C++/WinRT，显示器 `CreateForMonitor` / 窗口 `CreateForWindow`） |

### 4.2 ABI 要点

- 结构体尺寸（JNA 必须一致）：`klive_monitor_desc` 292、`klive_window_desc` 376、
  `klive_mirror_config` 32、`klive_mirror_stats` 32。
- 宽字段放结构体开头、总大小保持 8 的倍数、不放 4 字节以下字段 —— 为了避开 JNA 与
  MSVC x64 默认对齐的差异。`klive_window_desc` 因此有一个 `int32_t reserved`。
- 字符串是定长 `char[]` + UTF-8（`ByteArray(n)` + 去尾部 0）。
- 错误 = 返回码 + `klive_last_message()`；`MirrorEngine.errorText()` 把码翻译成中文。

### 4.3 采集

- 选择逻辑：`source_kind == WINDOW` → 只能 WGC；否则按 `capture_backend` 选桌面复制或 WGC。
- 桌面复制：`AcquireNextFrame(16ms)`，`DXGI_ERROR_ACCESS_LOST` 时重建 duplication 后继续。
- WGC：worker 线程先 `winrt::init_apartment(multi_threaded)`；`CreateFreeThreaded` 帧池
  （2 帧、`B8G8R8A8_UNORM`）；`TryGetNextFrame` 轮询（没有新帧就小睡 2ms，最多 4 轮）；
  `ContentSize()` 变化时 `frame.Close()` 后 `Recreate` 帧池；`IsBorderRequired(false)` 用
  try/catch（Windows 11 才有）。
- 两种后端都把帧 `CopyResource` 到自己的纹理（`FrameCopy`，含 SRV 缓存），渲染循环只认
  `ID3D11Texture2D`。
- **光标行为不一致**：WGC 打开了 `IsCursorCaptureEnabled(true)`（画面带鼠标），
  桌面复制不带光标。

### 4.4 呈现

- 设备建在**源显示器所属显卡**；目标显示器挂在另一块卡时由 DWM 跨卡合成。
- 窗口：`WS_POPUP` + `WS_EX_TOPMOST | WS_EX_TOOLWINDOW`，铺满目标显示器且不进任务栏 / Alt+Tab；
  `Ctrl+Alt+Q` 退出，聚焦时 `Esc` 也退出。
- 外壳窗口：`DwmSetWindowAttribute(20，回退 19)` 开深色标题栏，标题文字由 DWM 画白字，
  与暗色面板一致。
- 渲染：D3D11 全屏四边形（`VSMain` 用 `SV_VertexID` 生成三角带）+ 线性采样 +
  `D3D11_CULL_NONE` + 显式 viewport + flip 模型交换链。
- 缩放：`scale_mode 0` 等比填充（留黑边）、`1` 拉伸铺满；参数走常量缓冲 `ScaleParams`。
- 统计：`frames` / `fps` / `frame_width` / `frame_height`，fps 每 500ms 采样一次。

### 4.5 Kotlin 侧

- [MirrorEngine.kt](../core/src/commonMain/kotlin/moe/lolosia/klive/capture/MirrorEngine.kt)：
  UI 依赖的端口（`monitors()` / `windows()` / `start()` / `stop()` / `stats()` / `openConsole()`）。
- [WasmMirrorEngine.kt](../ui/src/wasmJsMain/kotlin/moe/lolosia/klive/ui/engine/WasmMirrorEngine.kt)：
  走 `Bridge` 把请求转给 `klive_webview.dll`；浏览器里换成 `MockMirrorEngine`。
- [Bridge.kt](../ui/src/wasmJsMain/kotlin/moe/lolosia/klive/ui/bridge/Bridge.kt)：
  `postMessage` 请求 / 回包，5s 超时。
- [App.kt](../ui/src/commonMain/kotlin/moe/lolosia/klive/ui/App.kt)：双栏布局，左「采集源」右「目标显示器」；
  源侧有 显示器/窗口 页签与 桌面复制/WGC 切换（默认 WGC），页头有「打开终端 / 重新枚举」，
  底部是缩放 / 垂直同步 / 统计。
- 状态轮询：`LaunchedEffect` 每 300ms 读一次 stats，`running` 变 false 时展示 `lastMessage()`。

### 4.6 单 exe

- [plugin.json](../keel-plugin-klive/src/commonMain/resources/plugin.json)：`name` = `Kiger's Live Helper`，
  `logTag` = `Kiger's Live`；日志模块列按显示宽度补齐，中文 / 撇号不会打乱对齐。
- [build.gradle.kts](../keel-plugin-klive/build.gradle.kts)：`keelPlugin.executable` 开启，
  `console = false` 走 Windows GUI 子系统；launcher 取 `keel-launcher-dev-mingwX64`；
  产物 `build/keel/mingwX64/KigerLiveHelper.exe`，PE 版本资源用 `windows {}`。
  `include("…:keel-plugin-console:…@keel")` 把 console 插件一起摊进 bundle，`runPlugin(...)`
  让 `keelRun` 也能加载它。
- bundle 布局：`bundle.json` + `plugins/{klive,console}/{plugin.json,lib/mingwX64,resources}`；
  运行期从 PE 资源 `KEELBUNDLE` 读入内存，只有原生 DLL 物化到 `.cache/<id>/<version>/`。
- 工作根：`KEEL_HOME` → exe 目录 → 用户缓存目录（exe 目录不可写时自动回退并告警）。
- 「打开终端」链路：wasm 按钮 → `Bridge` 的 `openConsole` → `klive_webview.dll` 调用
  `klive_webview_config.open_console` → K/N `WebConsole.open()` →
  `Messenger.post(target="console", channel="console", payload="open")`。
  C++ 只做转发，不启动进程；窗口与 helper 都由 console 插件负责。

## 6. 已确认的设计决策

1. **两份二进制、一份 C ABI**：原生核心不认识 Kotlin，Kotlin 不碰 D3D11。为将来 keel 插件
   （Kotlin/Native cinterop）留路。
2. **`core` 与 `app` 必须分开**：Compose 编译器插件作用于整个工程，单工程 + 原生目标会因缺
   Compose Runtime 编译失败。
3. **采集抽象成 `FrameSource`**：渲染 / 缩放 / 统计逻辑只有一份，新增后端只加一个实现。
4. **帧必中转**（`CopyResource`）：DXGI / WGC 的帧纹理生命期只有一帧，直接持有会画到已释放资源。
5. **设备建在源卡上**：跨显卡 Present 交给 DWM，不要自己做拷贝。
6. **UI 默认 WGC**：避免和 OBS 的「显示器采集」抢独占；要极限性能时手动切桌面复制。
7. **原生层不抛异常给 JNA**：全部错误转成返回码 + 中文 message。

## 7. 已知缺口 / 下一步

1. **窗口采集的生命周期**：窗口关闭 / 最小化 / 被移动到别的显示器时，WGC 会话可能停帧或
   报 `hresult`；目前只会把错误抛给 UI，没有「跟随窗口」或自动重建。
2. **光标绘制**：桌面复制不画鼠标；要么在渲染循环里画一个软件光标，要么统一走 WGC。
3. **HDR**：桌面是 FP16 桌面格式时按 SDR 直出，颜色偏亮，未做色调映射。
4. **配置持久化**：采集源、目标屏、缩放模式、后端都没存；关掉就忘。
5. **显示器热插拔**：启动后拔插显示器 / 改分辨率，桌面复制靠 `ACCESS_LOST` 扛住，
   但窗口位置与枚举列表不会刷新（UI 要手动「重新枚举」）。
6. **多路镜像**：原生层是进程级单例会话，要同时镜像两路得先改造会话模型。
7. **键盘快捷键开关**：目前只有退出热键，没有「暂停 / 恢复」。
8. **单 exe 体积**：当前约 41MB（debug launcher + debug 插件 dll + 两份 wasm + console helper）；
   release launcher 上游尚未发布，体积也未裁剪。
9. **局域网串流**：留给 keel 插件方向，原生层需要把「取得一帧」暴露成可复用的拉取接口
   （现在是渲染循环内部驱动）。

## 8. 易踩的坑

> 每条都写了症状，便于直接搜到。

- **JNA 加载 DLL 后 `std::mutex` 加锁会访问违例（AV）**，而同样的函数用 PowerShell P/Invoke
  调用却正常。原生层一律用 `SRWLOCK` + `SrwExclusiveLock`（`internal.h`），**不要**换回
  `std::mutex` / `std::lock_guard`。
- **全屏四边形被背面剔除**：不设 `D3D11_CULL_NONE` 且不给 viewport 时，画面全黑但帧率正常。
  重建 render target 时必须同时重设 viewport。
- **不 join 会 abort**：worker 线程可能因错误 / Esc 自行结束，此时 `std::thread` 仍 joinable；
  `klive_mirror_start` 和 `klive_mirror_stop` 都要 `join`，否则退出时 `std::terminate`。
- **JNA 结构体对齐**：MSVC x64 默认 8 字节对齐，JNA 不一定。表现是「枚举第 2 条开始全是乱码」
  或「启动后参数错位」。规矩见 AGENTS.md §4（宽字段前置、总大小 8 的倍数、不放小整型）。
- **`IDirect3DDxgiInterfaceAccess` 不在全局命名空间**：它声明在
  `::Windows::Graphics::DirectX::Direct3D11` 里。直接写裸名字会报「未声明的标识符」，
  连带一串 `winrt::com_ptr` 模板推导错误。取 WGC 帧纹理的正确写法：
  `winrt::get_unknown(surface)` → `QueryInterface(IID_PPV_ARGS(&access))` → `access->GetInterface(...)`。
- **`frame_source.h` 必须自己 include `<d3d11.h>`**：`internal.h` 只拉 `dxgi1_2.h`，
  漏了会得到一大片「`ID3D11Device` 未声明 / `ComPtr<T>` 模板参数无效」的连锁报错，
  真正的根因在第一条错误里。
- **WGC 帧池必须先 `frame.Close()` 再 `Recreate`**：尺寸变化时如果还持有帧就重建，
  行为未定义。当前实现是「尺寸不一致就丢帧 + 重建，下一轮重来」。
- **`IsBorderRequired(false)` 只在 Windows 11 有**，Win10 会抛 `hresult_error`，
  必须 try/catch 吞掉。
- **窗口枚举要过滤**：不可见 / 无标题 / `WS_EX_TOOLWINDOW` / 被 DWM cloak（关掉的 UWP）/
  本进程窗口都要排除，否则列表里全是幽灵条目。cloaked 判定用 `DwmGetWindowAttribute(DWMWA_CLOAKED)`。
- **窗口采集在静态画面上 fps 很低**是正常现象（WGC 只出变化帧），不要当性能 bug 排查。
- **桌面复制是独占的**：OBS 用「显示器采集（Desktop Duplication）」时 klive 启动会拿到
  `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`，提示已写明「改用 WGC 后端或窗口采集」。
  OBS 切到 WGC 采集方式后两者可共存。
- **DPI**：`klive_initialize()` 里设 `PER_MONITOR_AWARE_V2`；漏了会导致窗口定位与
  枚举坐标不一致（缩放 125% / 150% 的机器上必现）。
- **截图验证**：翻转模型（flip）窗口用 GDI `PrintWindow` / `CopyFromScreen` 可能得到白屏，
  临时办法是在原生层把 backbuffer 导出 BMP；截图前记得 `SetProcessDpiAwarenessContext(-4)`。
- **PowerShell 的 heredoc 不可用**：`git commit -m "$(cat <<'EOF' ...)"` 会 ParseError，
  中文提交信息用多个 `-m` 参数传。
- **cinterop 的包名来自 `.def` 文件名**：`klive_webview.def` 生成的是 `klive_webview.*`，
  不是 interop 名 `klivewebview`。写错包名会得到「Unresolved reference: klivewebview」
  以及一堆 `alloc<...>` / 结构体字段的连锁报错。
- **`Microsoft::WRL::Callback` 在 `<wrl/event.h>`**：只 include `<wrl/implements.h>` 会报
  「`Callback` 不是 `Microsoft::WRL` 的成员」，并让后面的 `CreateCoreWebView2...` 参数数量
  对不上（lambda 被当成参数而不是 handler）。
- **WebView2 的 `WebResourceRequested` 只对匹配的过滤器生效**：拦截自定义主机时用
  `AddWebResourceRequestedFilter(L"https://klive.local/*", ...)`；HTML 里的 `.wasm`
  必须显式回 `application/wasm`，否则 Compose 白屏、console 报 `instantiateStreaming` 失败。
- **keel 的 START 握手只有 5s**：`klive_webview_start` 最多等 3s 就返回，超时按成功处理，
  面板会在 WebView2 就绪后自己出现；否则会把插件启动拖超时。
- **`.keel` 里 DLL 的依赖不会自动搜自身目录**：插件侧用
  `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)`
  才能找到同目录的 `WebView2Loader.dll`。
- **`-Pkeel.run.serveMs=...` 在 PowerShell 里要加引号**：否则 `-Pkeel` 被当成 PowerShell
  参数，Gradle 会报 `Task '.run.serveMs=...' not found`。
- **单 exe 会在自己目录写 `plugins/` 与 `.cache/`**：放在 `Program Files` 这类只读目录时
  启动日志会出现「安装目录不可写，工作目录改用 …\AppData\…」的 WARN，随后正常启动；
  预置配置 / 覆盖插件要写到这个回退后的工作根，而不是 exe 目录。
- **GUI 子系统看不到 stdout**：`console = false` 后双击 / 命令行启动都不会有日志输出；
  调试时设 `KEEL_CONSOLE=1`（或加 `--console`）附着控制台，正式使用走「打开终端」。
- **WebView2 回调进入 K/N 的边界**：`open_console` 在 UI 线程上执行，只允许投递
  `Messenger.post` 这类线程安全的单向消息；不要在里面访问 `ctx.scheduler` / `ctx.scope`
  或做阻塞操作，异常也不能抛回 C（否则进程会 terminate）。
- **`klive_webview_config` 加字段是破坏性变更**：`klive_webview_start` 会读结构体尾部的
  `open_console`，旧调用方只分配旧尺寸就会越界读。改头文件后必须同时重编
  `klive_webview.dll`、keel 插件与 `klive_webview_smoke`。
- **重载后「注册窗口类失败（GetLastError=1410）」**：插件停用会卸下 `klive_webview.dll`，
  但窗口类还挂在进程里，旧 wndproc 指向已卸载的代码。消息循环退出后必须
  `UnregisterClassW(kWindowClass, ModuleHandle())`；`RegisterClassExW` 收到 1410 时
  按已注册处理，避免异常路径把插件启动卡死。
- **Host 的 `--plugins` 可以是相对路径**，此时 `materialize` 返回的也是相对路径；
  `LoadLibraryExW` 的 `LOAD_LIBRARY_SEARCH_*` 只认绝对路径（错误码 87）。
  K/N 侧用 `GetFullPathNameW` 转绝对路径，C++ 侧同样在 `start` 入口做一次。
- **Compose `Text` 默认颜色是黑色**：`MaterialTheme` 只提供配色，不设置 `LocalContentColor`；
  根布局只加 `background(...)` 而没有 `Surface` 包裹时，没写 `color` 的 Text（如页头大标题）
  会黑字压在深色背景上。给这类 Text 显式 `onBackground` / `onSurface`，或把根包进 `Surface`。
- **wasm 面板中文全是豆腐块**：Compose 的 wasm 渲染没有系统字体管理器，只带一份无 CJK
  的默认字体。做法是外壳在 `ServeResource` 里把 `/system-font` 映射到
  `%WINDIR%\Fonts\Deng.ttf`（回退 msyh.ttc / simhei.ttf / simsun.ttc），wasm 侧用
  `window.fetch` + `Int8Array(...).toByteArray()`（`kotlinx-browser`）拿到字节，
  再用 `Font("klive-system", bytes)` 组成 `FontFamily` 塞进 `Typography`。
  不能只改 `LocalTextStyle`：Material3 的每个 Text 样式都显式带 `fontFamily`。
- **WebView2 字发虚 / 窗口偏小（125% 缩放下）**：宿主进程可能已经被别的模块设成
  system aware，`SetProcessDpiAwarenessContext` 会失败。UI 线程必须再调
  `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)`；窗口尺寸按
  `GetDpiForSystem()/96` 把逻辑像素换算成物理像素；并显式
  `ICoreWebView2Controller3::put_RasterizationScale(dpi/96)`，否则 WebView2 按 96 DPI
  渲染后被系统拉伸。`WM_DPICHANGED` 也要按建议矩形重排。
- **PowerShell 截图会自己把画面弄糊**：默认进程是 DPI-unaware，`GetWindowRect` /
  `CopyFromScreen` 拿到的是逻辑坐标，125% 下 1400×950 的窗口会被按 1120×760 虚拟化后重采样。
  截图前先 `SetProcessDpiAwarenessContext(-4)`，再按 `GetWindowRect` 抓 1:1 画面。
