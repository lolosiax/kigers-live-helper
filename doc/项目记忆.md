## 1. 项目定位

- **klive**：Windows 桌面屏幕镜像工具。把一台显示器（或一个窗口）实时镜像到另一台显示器。
- 形态：C++/D3D11 原生核心（`native/`，产出 `klive_capture.dll`）+ Kotlin/JVM + Compose Desktop
  外壳（`app/`，JNA 调原生库）+ 纯 Kotlin 共享模型（`core/`，KMP）。
- 包根 `moe.lolosia.klive`，版本 `0.1.0`。
- 长期方向：镜像/串流核心要能被 keel 插件（局域网 WebRTC / RTSP）复用，所以原生层只暴露 C ABI。

## 2. 当前目录与构建

```
native/   C++ 核心（独立 CMake 工程）
core/     KMP：jvm + mingwX64 + linuxX64，只放共享模型
app/      Compose Desktop 外壳 + JNA 绑定 + 原生构建任务
doc/      长任务记忆
```

工具链：Kotlin `2.4.0`、Compose Multiplatform `1.11.1`、material3 `1.11.0-alpha07`、
JNA `5.17.0`、coroutines `1.11.0`、JDK 21 toolchain、CMake 3.20+、VS2022（MSVC）。

```powershell
.\gradlew.bat :app:nativeBuild    # -> app/build/native/cmake/Release/klive_capture.dll
.\gradlew.bat :app:run            # 控制面板（自动先编原生库）
.\gradlew.bat :app:probe          # 无窗口自检：枚举显示器 + 窗口
.\gradlew.bat :app:packageMsi     # MSI（DLL 作为资源打进 jar，运行时解压到临时目录）
```

- 开发时 `run` / `probe` 通过 `-Dklive.native.path` 直接指向构建产物，不走 jar 资源解压。
- `kotlin.native.ignoreDisabledTargets=true`：`core` 的 linuxX64 只在 Windows 上做编译校验。
- 配置缓存关闭（`org.gradle.configuration-cache=false`），首个版本不折腾。
- 没有自动化测试；验证靠 probe + 手动点「开始镜像」+ 帧率 / 画面尺寸读数。

## 4. 已实现细节

### 4.1 原生层结构

| 文件 | 职责 |
| --- | --- |
| `include/klive.h` | C ABI：结构体布局 + 导出函数，**唯一布局来源** |
| `src/internal.h` | `KliveOutput`（枚举结果）、`KliveMirrorSession`（原子状态 + worker）、`SrwExclusiveLock` |
| `src/klive_exports.cpp` | 导出函数实现 |
| `src/klive_monitor.cpp` | DXGI 枚举显示器、`EnumWindows` 枚举窗口、错误消息缓冲 |
| `src/klive_mirror.cpp` | 镜像窗口（无边框置顶）+ 渲染循环 + 缩放 + 帧率统计 |
| `src/frame_source.h/.cpp` | `FrameSource` 接口、`FrameCopy` 中转纹理、DXGI 错误文案 |
| `src/klive_duplication.cpp` | 桌面复制后端（`ACCESS_LOST` 自动重建） |
| `src/klive_wgc.cpp` | WGC 后端（C++/WinRT，显示器 `CreateForMonitor` / 窗口 `CreateForWindow`） |

### 4.2 ABI 要点

- 结构体尺寸（JNA 必须一致）：`klive_monitor_desc` 292、`klive_window_desc` 376、
  `klive_mirror_config` 32、`klive_mirror_stats` 32。
- 宽字段放结构体开头、总大小保持 8 的倍数、不放 4 字节以下字段 —— 为了避开 JNA 与
  MSVC x64 默认对齐的差异。`klive_window_desc` 因此有一个 `int32_t reserved`。
- 字符串是定长 `char[]` + UTF-8（`ByteArray(n)` + 去尾部 0）。
- 错误 = 返回码 + `klive_last_message()`；`MirrorEngine.errorText()` 把码翻译成中文。

### 4.3 采集

- 选择逻辑：`source_kind == WINDOW` → 只能 WGC；否则按 `capture_backend` 选桌面复制或 WGC。
- 桌面复制：`AcquireNextFrame(16ms)`，`DXGI_ERROR_ACCESS_LOST` 时重建 duplication 后继续。
- WGC：worker 线程先 `winrt::init_apartment(multi_threaded)`；`CreateFreeThreaded` 帧池
  （2 帧、`B8G8R8A8_UNORM`）；`TryGetNextFrame` 轮询（没有新帧就小睡 2ms，最多 4 轮）；
  `ContentSize()` 变化时 `frame.Close()` 后 `Recreate` 帧池；`IsBorderRequired(false)` 用
  try/catch（Windows 11 才有）。
- 两种后端都把帧 `CopyResource` 到自己的纹理（`FrameCopy`，含 SRV 缓存），渲染循环只认
  `ID3D11Texture2D`。
- **光标行为不一致**：WGC 打开了 `IsCursorCaptureEnabled(true)`（画面带鼠标），
  桌面复制不带光标。

### 4.4 呈现

- 设备建在**源显示器所属显卡**；目标显示器挂在另一块卡时由 DWM 跨卡合成。
- 窗口：`WS_POPUP` + `WS_EX_TOPMOST`，铺满目标显示器；`Ctrl+Alt+Q` 退出，聚焦时 `Esc` 也退出。
- 渲染：D3D11 全屏四边形（`VSMain` 用 `SV_VertexID` 生成三角带）+ 线性采样 +
  `D3D11_CULL_NONE` + 显式 viewport + flip 模型交换链。
- 缩放：`scale_mode 0` 等比填充（留黑边）、`1` 拉伸铺满；参数走常量缓冲 `ScaleParams`。
- 统计：`frames` / `fps` / `frame_width` / `frame_height`，fps 每 500ms 采样一次。

### 4.5 Kotlin 外壳

- [KliveLibrary.kt](../app/src/main/kotlin/moe/lolosia/klive/capture/KliveLibrary.kt)：
  JNA 接口 + 四个结构体 + `KliveNativeLoader`（先看 `-Dklive.native.path`，否则从 jar 资源解压）。
- [MirrorEngine.kt](../app/src/main/kotlin/moe/lolosia/klive/capture/MirrorEngine.kt)：
  `monitors()` / `windows()` / `start()` / `stop()` / `stats()`，UI 只依赖它。
- [App.kt](../app/src/main/kotlin/moe/lolosia/klive/ui/App.kt)：双栏布局，左「采集源」右「目标显示器」；
  源侧有 显示器/窗口 页签与 桌面复制/WGC 切换（默认 WGC），底部是缩放 / 垂直同步 / 统计。
- 状态轮询：`LaunchedEffect` 每 300ms 读一次 stats，`running` 变 false 时展示 `last_message()`。

## 6. 已确认的设计决策

1. **两份二进制、一份 C ABI**：原生核心不认识 Kotlin，Kotlin 不碰 D3D11。为将来 keel 插件
   （Kotlin/Native cinterop）留路。
2. **`core` 与 `app` 必须分开**：Compose 编译器插件作用于整个工程，单工程 + 原生目标会因缺
   Compose Runtime 编译失败。
3. **采集抽象成 `FrameSource`**：渲染 / 缩放 / 统计逻辑只有一份，新增后端只加一个实现。
4. **帧必中转**（`CopyResource`）：DXGI / WGC 的帧纹理生命期只有一帧，直接持有会画到已释放资源。
5. **设备建在源卡上**：跨显卡 Present 交给 DWM，不要自己做拷贝。
6. **UI 默认 WGC**：避免和 OBS 的「显示器采集」抢独占；要极限性能时手动切桌面复制。
7. **原生层不抛异常给 JNA**：全部错误转成返回码 + 中文 message。

## 7. 已知缺口 / 下一步

1. **窗口采集的生命周期**：窗口关闭 / 最小化 / 被移动到别的显示器时，WGC 会话可能停帧或
   报 `hresult`；目前只会把错误抛给 UI，没有「跟随窗口」或自动重建。
2. **光标绘制**：桌面复制不画鼠标；要么在渲染循环里画一个软件光标，要么统一走 WGC。
3. **HDR**：桌面是 FP16 桌面格式时按 SDR 直出，颜色偏亮，未做色调映射。
4. **配置持久化**：采集源、目标屏、缩放模式、后端都没存；关掉就忘。
5. **显示器热插拔**：启动后拔插显示器 / 改分辨率，桌面复制靠 `ACCESS_LOST` 扛住，
   但窗口位置与枚举列表不会刷新（UI 要手动「重新枚举」）。
6. **多路镜像**：原生层是进程级单例会话，要同时镜像两路得先改造会话模型。
7. **键盘快捷键开关**：目前只有退出热键，没有「暂停 / 恢复」。
8. **打包体积**：MSI 会把整个 Compose 运行时打进去；尚未做 jlink / 裁剪。
9. **局域网串流**：留给 keel 插件方向，原生层需要把「取得一帧」暴露成可复用的拉取接口
   （现在是渲染循环内部驱动）。

## 8. 易踩的坑

> 每条都写了症状，便于直接搜到。

- **JNA 加载 DLL 后 `std::mutex` 加锁会访问违例（AV）**，而同样的函数用 PowerShell P/Invoke
  调用却正常。原生层一律用 `SRWLOCK` + `SrwExclusiveLock`（`internal.h`），**不要**换回
  `std::mutex` / `std::lock_guard`。
- **全屏四边形被背面剔除**：不设 `D3D11_CULL_NONE` 且不给 viewport 时，画面全黑但帧率正常。
  重建 render target 时必须同时重设 viewport。
- **不 join 会 abort**：worker 线程可能因错误 / Esc 自行结束，此时 `std::thread` 仍 joinable；
  `klive_mirror_start` 和 `klive_mirror_stop` 都要 `join`，否则退出时 `std::terminate`。
- **JNA 结构体对齐**：MSVC x64 默认 8 字节对齐，JNA 不一定。表现是「枚举第 2 条开始全是乱码」
  或「启动后参数错位」。规矩见 AGENTS.md §4（宽字段前置、总大小 8 的倍数、不放小整型）。
- **`IDirect3DDxgiInterfaceAccess` 不在全局命名空间**：它声明在
  `::Windows::Graphics::DirectX::Direct3D11` 里。直接写裸名字会报「未声明的标识符」，
  连带一串 `winrt::com_ptr` 模板推导错误。取 WGC 帧纹理的正确写法：
  `winrt::get_unknown(surface)` → `QueryInterface(IID_PPV_ARGS(&access))` → `access->GetInterface(...)`。
- **`frame_source.h` 必须自己 include `<d3d11.h>`**：`internal.h` 只拉 `dxgi1_2.h`，
  漏了会得到一大片「`ID3D11Device` 未声明 / `ComPtr<T>` 模板参数无效」的连锁报错，
  真正的根因在第一条错误里。
- **WGC 帧池必须先 `frame.Close()` 再 `Recreate`**：尺寸变化时如果还持有帧就重建，
  行为未定义。当前实现是「尺寸不一致就丢帧 + 重建，下一轮重来」。
- **`IsBorderRequired(false)` 只在 Windows 11 有**，Win10 会抛 `hresult_error`，
  必须 try/catch 吞掉。
- **窗口枚举要过滤**：不可见 / 无标题 / `WS_EX_TOOLWINDOW` / 被 DWM cloak（关掉的 UWP）/
  本进程窗口都要排除，否则列表里全是幽灵条目。cloaked 判定用 `DwmGetWindowAttribute(DWMWA_CLOAKED)`。
- **窗口采集在静态画面上 fps 很低**是正常现象（WGC 只出变化帧），不要当性能 bug 排查。
- **桌面复制是独占的**：OBS 用「显示器采集（Desktop Duplication）」时 klive 启动会拿到
  `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`，提示已写明「改用 WGC 后端或窗口采集」。
  OBS 切到 WGC 采集方式后两者可共存。
- **DPI**：`klive_initialize()` 里设 `PER_MONITOR_AWARE_V2`；漏了会导致窗口定位与
  枚举坐标不一致（缩放 125% / 150% 的机器上必现）。
- **截图验证**：翻转模型（flip）窗口用 GDI `PrintWindow` / `CopyFromScreen` 可能得到白屏，
  临时办法是在原生层把 backbuffer 导出 BMP；截图前记得 `SetProcessDpiAwarenessContext(-4)`。
- **PowerShell 的 heredoc 不可用**：`git commit -m "$(cat <<'EOF' ...)"` 会 ParseError，
  中文提交信息用多个 `-m` 参数传。
